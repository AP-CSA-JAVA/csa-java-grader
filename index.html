How grading works
  • Compilation & Output — compiled as Java 8, the course version. If it only compiles as Java 17 (it used var, records, switch arrows…), it's graded as Java 17 with no penalty and marked JAVA 17, and the newer features are listed for the student. The assignment's checks run against the code and against scripted runs where the grader types the answers. A problem that repeats across runs counts once. Doesn't compile → 2 (≤ 2 errors) or 1.
  • Documentation & Style — Oracle code conventions. Each type of mistake counts once; the student sees every line where it happened. The header is not style-checked.
  • Submission — a .java file plus a test cases document, a screenshot, or a comment in the code labeled TEST CASE 1:, TEST CASE 2:… The grader only confirms they exist; you still read them.
  • Header — −1 if missing or any field is blank or still a placeholder like [Your Full Name]. Partner is optional (None, N/A or blank are fine).
  • Suggested — average of the three columns, never above Compilation & Output, then the grading-note caps and the header deduction. Type in Final to override.
  • Correction sheets — a printable PDF for each student (at most two pages) with the suggested score, a numbered fix list and the style notes. Print correction sheets makes one PDF for the whole class, two pages per student, so printing double-sided gives one sheet of paper each.
  • Class summary — a PDF for you, not the students: the class average and score spread, every student's three columns, header deduction, suggested and final score, and the most common program and style mistakes with who made them. Save one after each grading run as a record.
  • Assignments — only “Any assignment” is built in. Your assignment files live in your private repository: download it as a zip (Code → Download ZIP) and click Load assignments. They're kept in this browser only; load the zip again after editing an assignment or on another computer.
  • Email students — sends each student their feedback and correction sheet through your own Google Apps Script mailer (set up once; see EMAIL-SETUP.md). Load a Canvas gradebook export as the roster so each student is matched to an email address by Canvas ID. A test run sends to you first, and the mailer's sent log stops a student from getting the same assignment twice.
  • Everything runs in this browser tab. Student code is never uploaded anywhere, except in the emails you choose to send. Results are saved in this browser so a reload picks up where it left off.
